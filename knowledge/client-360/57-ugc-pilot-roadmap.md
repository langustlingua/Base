# 57. Пилот UGC-реалити: порядок запуска

## 1. Стратегия

Начинать с одной семьи и одного креатора. Не строить маркетплейс креаторов до того, как:

- семья прошла полный цикл публикации;
- атрибуция пережила реальную оплату и возврат;
- statement сошёлся вручную;
- родитель понял процесс отзыва разрешения;
- креатору оказались полезны рекомендации;
- контент не мешал ребёнку учиться.

## 2. Решения владельца до разработки

- [ ] Рабочее или другое название рубрики «Я сам!».
- [ ] Кто первая пилотная семья.
- [ ] Креатор является родителем ребёнка или это разные лица.
- [ ] Публично: аватар / лицо / голос / только руки и экран.
- [ ] Псевдоним или настоящее имя.
- [ ] Какие площадки разрешены.
- [ ] Допустима ли платная реклама с материалами.
- [ ] Как долго материалы остаются публичными.
- [ ] Какая формула 50/50: после возвратов или после возвратов + прямых вычетов.
- [ ] Hold: 14 или 30 дней либо другой срок.
- [ ] Комиссия только с первой оплаты или также с продления.
- [ ] Юридический статус креатора и документы.
- [ ] Кто отвечает за ОРД/erid и отчётность.

## 3. Этап 0. Правила и безопасность

Результат:

- creator agreement;
- лицензия на контент;
- детальное разрешение родителя;
- child assent script;
- compensation appendix;
- attribution rules;
- refund/adjustment rules;
- advertising marking workflow;
- takedown SLA;
- incident contact.

Ни одного видео до подписания всех обязательных разрешений публиковать нельзя.

## 4. Этап 1. Закрытый контентный прототип

Сделать без публичной публикации:

- аватар;
- карточку ребёнка;
- девять кругов;
- один тестовый эпизод;
- mobile preview;
- creator upload;
- parent review;
- withdrawal simulation.

Использовать синтетические данные или специально одобренный тестовый материал.

## 5. Этап 2. Трекинг

Реализовать:

- creator ID и campaign ID;
- signed tracked link;
- UTM registry;
- first-party touch;
- link → session → lead;
- promo code;
- first/last/assisted touches;
- Yandex Metrica goals и e-commerce mirror;
- bot traffic flag;
- attribution conflict queue.

Проверить на искусственных сценариях с двумя браузерами, двумя креаторами и ручным вводом промокода.

## 6. Этап 3. Финансовый ledger

До реальной выплаты:

1. Синтетическая оплата.
2. Полный возврат.
3. Частичный возврат.
4. Два креатора претендуют на одну продажу.
5. Оплата после истечения окна.
6. Промокод без tracked click.
7. Click без промокода.
8. Refund после statement.
9. Manual adjustment.
10. Dispute и решение.

Сумма в кабинете должна воспроизводиться вручную по формуле.

## 7. Этап 4. Кабинет креатора MVP

Первый релиз:

- логин + 2FA;
- обзор воронки;
- tracked link и promo code;
- контент/статус проверки;
- публичная карточка preview;
- provisional/confirmed/payable ledger;
- уведомление об оплате/возврате;
- агрегированные вопросы;
- одна рекомендация;
- support/dispute.

Отложить:

- сложное сравнение креаторов;
- AI-автогенерацию сценариев;
- автоматические выплаты;
- predictive LTV;
- многоуровневую партнёрку;
- marketplace;
- публичный рейтинг.

## 8. Этап 5. Тихий запуск

- одна creator link;
- одна landing page;
- один promo code;
- один оффер;
- ограниченная аудитория;
- ручное подтверждение каждого материала;
- ручная сверка каждой оплаты;
- ежедневный privacy/attribution review;
- kill switch.

## 9. Этап 6. Первый сезон

План на четыре недели:

| Неделя | Контент | Продуктовая проверка |
|---|---|---|
| 0 | исходная точка и правила | baseline |
| 1 | первый вход и одно действие | first value |
| 2 | слова в разных упражнениях | repeat activity |
| 3 | текущая тема Spotlight | module/lesson |
| 4 | самостоятельность и честный итог | D7/D30 + parent diary |

## 10. Еженедельный review

Участники: Татьяна, креатор, контент/privacy reviewer.

Проверить:

- комфорт ребёнка;
- права и маркировку;
- опубликованные эпизоды;
- просмотры → переходы;
- переходы → заявки;
- заявки → trial;
- trial → first value;
- payment/refund;
- вопросы аудитории;
- одну рекомендацию;
- ошибки и takedown requests.

## 11. Критерии масштабирования

Добавлять второго креатора можно, если:

- consent/assent workflow прошёл без исключений;
- creator isolation проверена;
- нет PII в кабинете;
- атрибуция объяснима;
- statement воспроизводится;
- возврат корректно уменьшает долю;
- erid/reporting выполняются;
- ребёнок и родитель готовы продолжать;
- первый сезон дал минимум один содержательный кейс;
- процесс можно повторить без ручной памяти Татьяны.

## 12. Stop criteria

Пилот не масштабируется, если:

- семья ощущает давление;
- контент требует всё более личных сцен;
- большая часть продаж спорна по атрибуции;
- creator ожидает деньги, которые система показывает как окончательные раньше времени;
- возвраты/жалобы выше безопасного baseline;
- маркировка выполняется задним числом;
- рекомендации основаны на единичных вопросах;
- ручная работа Татьяны растёт быстрее продаж;
- невозможно удалить материал на всех собственных площадках.

## 13. Definition of Done пилота

- опубликована безопасная карточка с аватаром;
- есть минимум четыре эпизода;
- круги обновляются из approved assets;
- creator link и promo code работают;
- Client 360 видит полный путь;
- payment и refund создают ledger lines;
- креатор получает уведомления без PII;
- сформирован и принят statement;
- одна рекомендация проверена экспериментом;
- withdrawal/takedown drill выполнен;
- owner оформил письменное решение: масштабировать, изменить или закрыть.
