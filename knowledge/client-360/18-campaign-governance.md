# 18. Управление кампаниями и защита от ошибочной рассылки

## Состояния кампании

`draft → qa → dry_run → awaiting_approval → approved → scheduled → running → paused → completed / cancelled`

Кампания не может перескочить из `draft` в `running`.

## Dry run по умолчанию

До отдельного включения production любая отправка:

- считает аудиторию;
- показывает пять случайных и пять пограничных получателей;
- строит список исключённых и причины;
- рендерит все варианты персонализации;
- проверяет ссылки;
- отправляет только на внутренние тестовые адреса;
- не вызывает реальный WhatsApp и не меняет lifecycle клиента.

## Одобрение владельца

Для массовой отправки нужны:

- `approved_by`;
- `approved_at`;
- хэш версии аудитории;
- хэш шаблона;
- число получателей;
- срок действия одобрения;
- допустимое окно отправки.

Любое изменение аудитории, цены, CTA, шаблона или ссылки аннулирует одобрение.

Одобрение истекает, например, через 24 часа или до начала отправки — точный срок задаётся политикой. Старое одобрение нельзя переиспользовать для другой кампании.

## Предпусковой чек

- [ ] Цель и success event определены.
- [ ] Аудитория соответствует продукту, классу, региону и учебнику.
- [ ] Есть требуемое согласие.
- [ ] Opt-out, hard bounce, complaint и block исключены.
- [ ] Покупатели исключены из оффера, который уже купили.
- [ ] Открытые жалобы, возвраты, privacy requests и нерешённая поддержка исключены.
- [ ] Нет просроченного обещания сотрудника.
- [ ] Frequency cap соблюдён.
- [ ] Цена, срок и промокод взяты из актуального offer registry.
- [ ] Переменные имеют fallback.
- [ ] Все ссылки открываются на мобильном.
- [ ] UTM уникальны и корректны.
- [ ] Отписка работает.
- [ ] Reply-to контролируется человеком.
- [ ] Тест доставлен на Gmail, Mail.ru, Yandex и мобильное устройство.
- [ ] У кампании есть владелец, дата выключения и процедура паузы.

## Аварийная остановка

Кнопка `PAUSE ALL MARKETING` должна:

1. остановить новые отправки;
2. отменить ещё не переданные провайдеру задания;
3. не блокировать критические сервисные сообщения;
4. записать инициатора и причину;
5. показать, сколько сообщений уже ушло;
6. потребовать новое одобрение для возобновления.

## Защита от неправильной цены

Шаблон не хранит цену текстом. Он получает `offer_id`, а цена, срок, скидка и допустимые сегменты читаются из реестра офферов.

Если оффер истёк или аудитория не соответствует условиям, рендер блокируется. Нельзя автоматически подставлять другой тариф «чтобы письмо всё равно ушло».

## Пакет доказательств кампании

После отправки сохраняются:

- версия аудитории и запрос;
- шаблон;
- оффер;
- одобрение;
- число queued/sent/delivered/bounced;
- suppression;
- отписки и жалобы;
- целевые события;
- revenue с оговорённым окном атрибуции;
- решения об остановке.
