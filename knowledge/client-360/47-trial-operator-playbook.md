# 47. Ручная работа с пробными заявками

Эта инструкция нужна для первого запуска, пока события платформы и автоматизация реализованы не полностью.

## Рабочая очередь Гузель

Каждая заявка имеет только один текущий статус:

1. `NEW` — заявку ещё не проверили.
2. `ACCESS_SENT` — доступ отправлен.
3. `NO_LOGIN` — доступа не открывали.
4. `LOGGED_IN` — вошли, занятия не начались.
5. `STARTED` — начали урок.
6. `FIRST_VALUE` — выполнили упражнение.
7. `ENGAGED` — завершили урок или вернулись второй раз.
8. `CHECKOUT` — начали оплату.
9. `PAID` — платёж и доступ сверены.
10. `SUPPORT` — есть нерешённая проблема.
11. `DECLINED` — отказались или попросили не писать.
12. `EXPIRED` — пробник завершён без покупки.

## Утром

1. Проверить новые заявки и дубли.
2. Убедиться, что доступ действительно создан.
3. Проверить заявки без входа более двух часов.
4. Поднять все `SUPPORT`, оплаты без доступа и обещанные ответы.
5. Проверить, кому пробник заканчивается сегодня.
6. Исключить покупателей и отказавшихся из очереди продаж.
7. Подготовить сообщения, но при сомнении не отправлять до решения Татьяны.

## После каждого контакта

Записать:

- время;
- канал;
- кто связался;
- причину контакта;
- шаблон или краткий смысл;
- результат из справочника outcome codes;
- обещание и срок, если оно дано;
- следующий шаг и дату;
- запрет/согласие, если клиент его изменил.

Нельзя писать в заметке оценочные формулировки вроде «сложная мама». Нужны факты: «не принимает пароль», «просит написать после 19:00», «ребёнок болеет до пятницы».

## Развилка ответа

| Ответ родителя | Действие |
|---|---|
| «Не вижу письмо» | проверить адрес, spam/promotions, повторить безопасную ссылку |
| «Не входит» | открыть support case, запросить скрин без пароля |
| «Не знаю, какой урок» | попросить модуль или фото страницы учебника |
| «Не успели» | отметить причину; повторный доступ только после решения человека |
| «Было сложно» | выяснить конкретный урок и действие |
| «Сколько стоит?» | дать только актуальный оффер для правильного сегмента |
| «Дорого» | уточнить контекст, не спорить и не выдумывать рассрочку |
| «Подумаю» | согласовать один следующий контакт или закрыть продажную задачу |
| «Не пишите» | немедленно поставить global suppression |
| «Оплатила» | проверить платёж и доступ до поздравления |

## Вечером

- закрыть или перенести обещания с новой точной датой;
- перечислить нерешённые технические проблемы;
- сверить оплаты и активные доступы;
- отметить, сколько заявок дошли до входа и первого упражнения;
- передать Татьяне только решения, которые действительно требуют её участия;
- не оставлять заявку без следующего шага или понятной причины закрытия.

## Ежедневный короткий отчёт

```text
Новые заявки:
Доступ отправлен:
Не вошли > 2 часов:
Первый результат:
Активные пробники заканчиваются сегодня:
Начали оплату:
Оплатили и доступ подтверждён:
Открытые проблемы:
Просроченные обещания:
Нужны решения Татьяны:
```

## Контроль качества

Раз в неделю случайно проверить десять заявок:

- соответствует ли сообщение реальному состоянию;
- не было ли дублирования каналов;
- записан ли результат;
- остановилась ли серия после покупки/отказа;
- не использована ли смоленская цена для другого региона;
- не попали ли персональные данные в публичный GitHub или общий чат.
