# 12. Импорт `clients.json`, дубли и качество данных

## Правило

Файл примерно на 182 семьи не импортируется напрямую в рабочие таблицы. Сначала — staging, отчёт и подтверждение спорных совпадений.

## Конвейер

1. Скопировать исходник в закрытое хранилище.
2. Зафиксировать checksum и дату экспорта.
3. Загрузить в `staging_clients` без изменения.
4. Нормализовать телефоны, email, регистр, пробелы и даты.
5. Проверить обязательные поля.
6. Найти точные дубли.
7. Построить кандидатов на объединение.
8. Показать человеку спорные пары.
9. Создать families / guardians / students.
10. Сохранить карту `old_id → new_id`.
11. Сверить количество и контрольные суммы.
12. Удалить временную копию по утверждённому процессу.

## Нормализация

### Email

- trim;
- lower case;
- проверить синтаксис;
- не исправлять домен догадкой;
- сохранять исходное значение в staging, рабочее — нормализованное.

### Телефон

- привести к E.164;
- российские `8…` нормализовать только при подтверждённой стране;
- добавочный номер отдельно;
- не считать номера одинаковыми после обрезания последних цифр.

### Имя

- убрать двойные пробелы;
- сохранить исходное написание;
- не выводить пол из имени автоматически;
- не считать «Катя» и «Екатерина» одним человеком без других признаков.

## Уровни совпадения

| Уровень | Условие | Действие |
|---|---|---|
| Exact | одинаковый внешний ID | объединить автоматически |
| Strong | одинаковый нормализованный телефон | объединить с журналом |
| Medium | email + имя ребёнка / город | показать человеку |
| Weak | только email или похожее имя | не объединять автоматически |
| None | нет устойчивых признаков | новая семья |

## Отчёт после импорта

- строк в исходнике;
- создано семей;
- создано родителей;
- создано детей;
- точных дублей;
- спорных дублей;
- строк без контакта;
- некорректных email;
- некорректных телефонов;
- неизвестных классов;
- неизвестных источников;
- согласий с доказательством;
- контактов без маркетингового согласия.

## Ежедневные проверки

- один phone/email у слишком многих несвязанных семей;
- два активных trial одного ребёнка;
- успешная оплата без доступа;
- активный доступ после полного возврата;
- рассылка на hard bounce;
- маркетинг при opted_out;
- открытый case и активный sales journey;
- просроченная задача без ответственного;
- событие из будущего;
- отрицательная длительность сессии;
- сумма возврата больше платежа;
- неизвестная версия события.

## Исправление

Данные не исправляются молча. Записываются:

- старое значение;
- новое значение;
- источник исправления;
- автор;
- время;
- причина.
