# 46. Реализация воронки трёх пробных дней

Источник текстов: [`../post-lead-funnel-3-day-trial.md`](../post-lead-funnel-3-day-trial.md). Этот документ описывает не копирайтинг, а правила запуска.

## Состояния пробника

| State | Условие | Следующая цель |
|---|---|---|
| `created` | доступ создан, доставки ещё нет | доставить доступ |
| `delivered_no_login` | письмо принято, входа нет | первый вход |
| `logged_in_no_start` | вход есть, урок не открыт | выбрать тему |
| `started_no_value` | урок открыт, задания нет | первое упражнение |
| `first_value` | первое упражнение выполнено | завершить урок / вернуться |
| `engaged` | урок завершён или есть вторая сессия | показать оффер |
| `checkout` | оплата начата | завершить или помочь |
| `purchased` | платёж подтверждён и доступ сверён | onboarding |
| `expired_inactive` | пробник закончился без первого результата | причина / помощь |
| `expired_engaged` | пробник закончился после результата | возражение / оффер |
| `support_hold` | открыта проблема | решить проблему |
| `suppressed` | отказ, жалоба или запрет | ничего не отправлять |

Состояние вычисляется из событий. `support_hold`, `purchased` и `suppressed` имеют приоритет над календарём.

## Порядок обработки события

1. Проверить подпись webhook и дедупликацию `event_id`.
2. Связать событие с `family_id`, `trial_id` и `enrollment_id`.
3. Пересчитать состояние пробника.
4. Сначала применить глобальные стоп-правила.
5. Отменить сообщения, ставшие нерелевантными.
6. Найти одно наиболее приоритетное следующее действие.
7. Проверить consent, канал, quiet hours и frequency cap.
8. Создать delivery в состоянии `pending_approval` или `scheduled`.
9. После отправки сохранить версию шаблона, оффера и основание.
10. После целевого события закрыть automation run.

## Приоритет

`privacy/refusal > complaint/refund > support > payment/access mismatch > activation > learning help > offer > deadline > content`

Если ребёнок начал упражнение в момент, когда запланировано письмо «вы ещё не вошли», старое письмо отменяется. Если открыт support case, продажные сообщения не откладываются «на потом», а пересчитываются после закрытия кейса.

## Правила времени

- все расчёты хранятся в UTC;
- отправка показывается и планируется по часовому поясу семьи;
- обычное окно: 09:00–20:30 локального времени;
- критический сервис может выходить за окно только при документированной необходимости;
- не более двух автоматических контактов в сутки суммарно;
- WhatsApp не дублирует email с той же задачей;
- ручной ответ сотрудника отменяет ожидающую автоматику минимум до разбора.

## Пересечение с дедлайном Смоленска

Используются две независимые даты:

- `trial_ends_at` — конец доступа конкретной семьи;
- `offer_ends_at = 2026-10-05T21:00:00Z` для московского времени 00:00 6 октября.

| До конца акции | Поведение |
|---|---|
| больше 4 дней | обычная трёхдневная продуктовая серия |
| 2–4 дня | оффер после первого результата, затем одно дедлайн-письмо |
| меньше 48 часов | в первом релевантном оффере сразу точная дата; не обещать длинную серию |
| после дедлайна | смоленский оффер недоступен, шаблон не отправляется |

Календарный дедлайн не заменяет активацию: неактивному лиду сначала помогают войти. Исключение — короткое честное уведомление об условиях, если маркетинговое согласие действительно и времени объективно мало.

## Данные, без которых запуск запрещён

- проверенный `trial_ends_at`;
- точный `offer_id` и версия цены;
- признак сегмента Смоленска;
- статус покупки и reconciliation доступа;
- согласие для каждого маркетингового канала;
- suppression list;
- рабочая отписка;
- владелец кампании и срок одобрения;
- технический kill switch.

## Приёмочные тесты

| Сценарий | Ожидаемый результат |
|---|---|
| покупка за минуту до оффера | оффер отменён |
| первый вход после постановки no-login | no-login отменён |
| два одинаковых webhook | одно изменение состояния |
| support case открыт | продажи остановлены |
| ответ «не пишите» в WhatsApp | global suppression до следующей попытки отправки |
| лид не из Смоленска | цена 7 900 ₽ нигде не появляется |
| оффер истёк | ссылка и шаблон недоступны планировщику |
| checkout без оплаты | одно сообщение через 24 часа, затем задача человеку |
| payment success без доступа | срочная задача, не поздравительное письмо |
| нет consent для WhatsApp | используется разрешённый канал либо задача человеку |
| quiet hours | перенос на ближайшее допустимое окно |
| лимит уже исчерпан | менее приоритетное сообщение пропущено |

## Definition of Done

- все сценарии выше проходят на синтетических данных;
- dry run показывает получателя, причину, шаблон, оффер и стоп-условия;
- владелец одобряет конкретную версию кампании;
- тестовая покупка выключает все продажи;
- unsubscribe и ручной запрет срабатывают до следующей отправки;
- отчёт разделяет доставку, активацию, первый результат, оплату и жалобы;
- есть журнал, кто и когда запустил кампанию.
