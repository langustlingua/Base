# 49. Инвентаризация и восстановление доступа к ботам

Статус: выполнить до разработки  
Платформы: Telegram, MAX  

## Что уже найдено

В публичной Base есть только старый маркетинговый набросок «бот на 8 шагов» в `index.html`. Имена созданных ботов, usernames, токены, владельцы и настройки webhook в репозитории не документированы.

Старый сценарий с бонусами через 40 минут, оффером «на час» и «последним шансом» считать устаревшим. Он не должен попадать в production: искусственный дедлайн противоречит новой воронке LANGUST.

## Критическое правило

Токен бота равен паролю приложения. Его нельзя:

- писать в GitHub, Base, Notion без защищённого хранилища;
- отправлять в обычный чат или email;
- вставлять в скриншот;
- хранить в исходном коде;
- передавать через query string;
- использовать одновременно в staging и production.

В документации хранится только `secret_reference`, например `prod/telegram/langust-main`, но не значение.

## Telegram: восстановление инвентаря

1. Открыть официальный `@BotFather` с того Telegram-аккаунта, где создавались боты.
2. Выполнить `/mybots`.
3. Для каждого найденного бота записать публичное имя, `@username`, назначение, owner account и статус.
4. Проверить Description, About, Commands, Menu Button, Domain и Payments.
5. Если неизвестно, где использовался токен, считать его потенциально скомпрометированным.
6. Отозвать старый токен через BotFather и выпустить новый.
7. Новый токен сразу положить в secret manager; в рабочий документ записать только reference.
8. До подключения production ограничить бота тестовыми пользователями на уровне приложения.

Официальная техническая документация: [Telegram Bot API](https://core.telegram.org/bots/api).

## MAX: восстановление инвентаря

1. Войти тем же владельцем в `business.max.ru`.
2. Открыть раздел «Чат-боты».
3. Зафиксировать отображаемое имя, username/ID, статус модерации, владельца и описание.
4. В меню бота открыть настройки/интеграцию.
5. Если профиль и бот создавались через «MAX для бизнеса», проверить соответствующее мини-приложение или бизнес-бота.
6. Получить или перевыпустить токен; значение сохранить только в secret manager.
7. Проверить текущие subscriptions/webhooks и отключить неизвестные endpoints.
8. Проверить актуальный API domain перед разработкой.

По официальной документации MAX токен доступен в бизнес-платформе в настройках чат-бота; API использует заголовок `Authorization`. На 21 сентября 2026 актуальный домен — `platform-api2.max.ru`. Источник: [MAX API](https://dev.max.ru/docs-api).

## Реестр без секретов

| Поле | Пример значения |
|---|---|
| `bot_id` | UUID внутри Client 360 |
| `platform` | telegram / max |
| `environment` | staging / production |
| `public_name` | имя, которое видит родитель |
| `public_username` | публичный username |
| `platform_bot_id` | ID платформы |
| `purpose` | acquisition / trial / support |
| `owner` | владелец аккаунта |
| `status` | discovered / token_rotated / staging / active / disabled |
| `secret_reference` | путь в secret manager |
| `webhook_url_masked` | домен и тип endpoint без секрета |
| `commands_version` | версия меню |
| `flow_version` | версия воронки |
| `created_at` | время создания, если известно |
| `last_verified_at` | последняя проверка |
| `notes` | без токенов и PII |

## Рекомендуемая структура

Для первой версии нужен один основной бот на платформу, а не отдельный бот под каждую кампанию:

- Telegram-бот LANGUST;
- MAX-бот LANGUST;
- один общий backend;
- один набор flow IDs и событий;
- платформенные адаптеры кнопок, форматирования и webhook.

Источник кампании передаётся deep-link/start параметром, а не создаётся новым ботом.

## Чек-лист завершения инвентаризации

- [ ] Найдены все боты в BotFather.
- [ ] Найдены все боты в кабинете MAX.
- [ ] Определён владелец каждого аккаунта.
- [ ] Записаны публичные usernames/IDs.
- [ ] Неизвестные токены отозваны.
- [ ] Новые токены сохранены в secret manager.
- [ ] Старые webhooks отключены или подтверждены.
- [ ] Staging и production разделены.
- [ ] Удалены токены из локальных файлов и истории репозитория, если они там когда-либо были.
- [ ] Включён secret scan.
- [ ] Назначена следующая дата проверки доступа.

## Если владелец аккаунта потерян

Не пытаться обходить доступ. Нужно установить, с какого аккаунта создавался бот, использовать официальное восстановление аккаунта и поддержку платформы. Если восстановить ownership нельзя, создаётся новый официальный бот, старый публично помечается неактуальным при наличии доступа, а пользователи переводятся только разрешённым способом.
