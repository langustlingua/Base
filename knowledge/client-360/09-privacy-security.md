# 09. Приватность и безопасность

Это продуктовая спецификация, а не юридическое заключение. Перед запуском реальной базы и трансграничных интеграций нужна проверка применимых требований по месту деятельности, клиентам, серверам и подрядчикам.

## Базовые принципы

1. Законная и прозрачная цель.
2. Минимизация: собирать только необходимое.
3. Точность и возможность исправления.
4. Ограничение срока хранения.
5. Конфиденциальность и безопасность.
6. Подотчётность: уметь объяснить, откуда поле и зачем оно нужно.
7. Защита по умолчанию, особенно для данных детей.

## Контуры данных

| Контур | Примеры | Доступ |
|---|---|---|
| Публичный | Base, схемы, шаблоны | всем |
| Операционный | контакты, задачи, обучение | Татьяна, ограниченные сотрудники |
| Финансовый | оплаты, возвраты, чеки | владелец / бухгалтерия |
| Ограниченный | данные детей, жалобы, специальные заметки | минимум людей |
| Секреты | токены API, пароли, ключи | секрет-хранилище, не CRM и не GitHub |

## Согласия

Нужны отдельные решения для:

- обработки данных для заявки и обучения;
- маркетингового email;
- маркетинга в мессенджере;
- необязательной аналитики / cookies, где требуется;
- публикации отзыва, фото или истории;
- поздравлений с днём рождения;
- передачи конкретным подрядчикам, если применимо.

Одна общая галочка «согласен со всем» ухудшает доказуемость и свободу выбора. Отказ от маркетинга не должен лишать клиента купленного курса и необходимых сервисных писем.

## Дети

- Основной контакт — родитель / законный представитель.
- Не отправлять маркетинг напрямую младшему школьнику.
- Не просить у ребёнка телефон и email без необходимости.
- Точную дату рождения собирать только при документированной цели.
- Не хранить школьный адрес, класс с буквой, расписание и геолокацию «для удобства».
- Отзывы, фото и учебные истории публиковать только при отдельном разрешении с понятным объёмом использования.
- Профилирование не должно приводить к несправедливым или унизительным выводам о способностях ребёнка.

## Роли

| Роль | Разрешено |
|---|---|
| Владелец | настройки, экспорт, удаления, финансы |
| Помощник | заявки, контакты, задачи, поддержка; без массового экспорта и секретов |
| Преподаватель | ученики и учебный прогресс; минимум финансов |
| Бухгалтер | платежи и документы; минимум учебных заметок |
| Маркетолог | обезличенные сегменты и кампании; без свободной выгрузки детей |
| Система | только разрешённые автоматические действия |

## Аудит

Логировать:

- вход сотрудника;
- просмотр ограниченной карточки;
- экспорт;
- изменение контакта;
- изменение согласия;
- объединение дублей;
- удаление / обезличивание;
- ручное изменение оплаты или доступа;
- массовую отправку.

Аудит-лог не редактируется обычными пользователями.

## Сроки хранения

Нельзя назначать один вечный срок «для всего». Создать таблицу `purpose → data → basis → retention → deletion action`.

Пример проектного подхода, который нужно юридически проверить:

- неотправленная / недействительная заявка — короткий срок;
- маркетинговый профиль — до отзыва плюс технический suppression минимумом данных;
- учебная активность — пока нужна для оказания услуги и отчёта, затем агрегировать / удалить;
- поддержка — ограниченный срок после закрытия;
- платежные и бухгалтерские записи — срок по применимому налоговому и бухгалтерскому праву;
- аудит безопасности — отдельный срок;
- резервные копии — ограниченный цикл с автоматическим уничтожением.

## Права и запросы

Нужен процесс:

- узнать, какие данные есть;
- исправить;
- получить копию;
- отозвать согласие;
- отказаться от маркетинга;
- удалить или ограничить обработку, когда это применимо;
- возразить против профилирования;
- получить объяснение источника данных.

Запрос создаёт case с проверкой личности, сроком, исполнителем и протоколом результата.

## Инциденты

План:

1. Остановить утечку / доступ.
2. Зафиксировать время, системы и затронутые категории.
3. Не удалять доказательства.
4. Оценить риск для родителей и детей.
5. Привлечь ответственного за право и безопасность.
6. Выполнить обязательные уведомления в применимые сроки.
7. Исправить причину.
8. Задокументировать решение.
