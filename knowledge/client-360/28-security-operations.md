# 28. Безопасность аккаунтов и операций

## Реестр систем

Для каждого сервиса:

- владелец;
- URL;
- тип данных;
- критичность;
- администраторы;
- 2FA;
- способ восстановления;
- резервный код — в секрет-хранилище;
- OAuth connections;
- API keys;
- дата последней ревизии;
- процедура отключения сотрудника.

## Входы и алерты

Логировать и оповещать:

- новый браузер / страна;
- несколько неудачных входов;
- отключение 2FA;
- создание API key;
- массовый экспорт;
- смена платёжных или DNS-настроек;
- выдача admin-роли;
- изменение suppression / consent;
- необычная массовая отправка.

Новый вход из Amsterdam сам по себе не доказывает взлом, но требует сверки с реальным местом/устройством и активными сессиями.

## 2FA и восстановление

- уникальный пароль для каждого сервиса;
- password manager;
- 2FA через приложение / ключ, где возможно;
- резервные коды вне почтового ящика;
- минимум два контролируемых способа восстановления для критических аккаунтов;
- ежеквартальная проверка;
- никакой передачи пароля Гузель в сообщении.

## API keys и токены

- secrets manager / переменные окружения;
- отдельный ключ production и staging;
- минимальные scopes;
- владелец и дата истечения;
- ротация;
- отзыв при уходе сотрудника;
- сканирование репозитория;
- токен никогда не помещается в URL аналитики, issue или скриншот.

## OAuth

Раз в квартал:

- выгрузить активные приложения Google и других аккаунтов;
- удалить неиспользуемые;
- проверить scopes;
- задокументировать OpenAI, Canva и другие подключения;
- сменить владельца, если аккаунт сотрудника больше не используется.

## Резервное копирование

Минимум:

- зашифрованный backup закрытой базы;
- несколько точек во времени;
- копия вне основного сервера;
- ограниченный доступ;
- журнал успеха;
- регулярный тест восстановления;
- автоматическое истечение старых копий.

Backup, который никогда не восстанавливали, нельзя считать рабочим.

## Среды

- production и staging не используют одну базу;
- тестовые email/телефоны явно маркированы;
- тестовый платёжный режим отделён;
- production sending выключен по умолчанию;
- debug logs не содержат PII и secrets;
- HTTPS обязателен;
- shared test account не используется в production.

## Security review перед запуском

- dependency audit;
- secret scan;
- access control tests;
- rate limits;
- CSRF/XSS/SQL injection review;
- password reset tests;
- public link enumeration test;
- webhook signature validation;
- backup restore test;
- внешнее сканирование после развёртывания.

Если HawkScan или аналог не запускался, это явно отмечается как незакрытый контроль, а не считается выполненным.
