# 30. QA и выпуск

## Перед изменением схемы

- [ ] Миграция обратима или есть план rollback.
- [ ] Старые версии приложения совместимы на время выкладки.
- [ ] Backup создан и проверен.
- [ ] Индексы оценены.
- [ ] PII-поля отмечены.
- [ ] Роли обновлены.
- [ ] Retention process знает новое поле.

## Перед новой автоматизацией

- [ ] Событие существует и стабильно.
- [ ] Eligibility и exclusions написаны явно.
- [ ] Stop events есть.
- [ ] Frequency cap есть.
- [ ] Повторная доставка события не дублирует сообщение.
- [ ] Покупка / отказ / case останавливают нужную ветку.
- [ ] Dry run пройден.
- [ ] Fallback переменных проверен.
- [ ] Отписка и reply работают.
- [ ] Владелец и дата выключения назначены.

## Перед импортом

- [ ] Исходник в закрытом месте.
- [ ] Checksum записан.
- [ ] Staging отделён.
- [ ] Нормализация протестирована.
- [ ] Дубли показаны.
- [ ] Consent не придуман.
- [ ] Контрольные количества совпадают.
- [ ] Есть rollback.
- [ ] Логи не содержат PII сверх необходимого.

## Перед релизом кабинета

- [ ] HTTPS.
- [ ] Production/staging разделены.
- [ ] Email verification.
- [ ] Password reset.
- [ ] Rate limiting.
- [ ] Access control на каждую роль.
- [ ] Parent видит только свою семью.
- [ ] Public progress links непредсказуемы и отзываются.
- [ ] Analytics не получает PII.
- [ ] Политика описывает прогресс и кабинет.
- [ ] Backup restore проверен.
- [ ] Error monitoring включён.
- [ ] Security scan выполнен или риск явно открыт.

## Тестовые сценарии

1. Одна мама, один ребёнок.
2. Одна семья, двое детей и разные курсы.
3. Два родителя с разными разрешениями.
4. Повторная заявка существующей семьи.
5. Неверный email.
6. Hard bounce после trial_created.
7. Оплата прошла, webhook повторился трижды.
8. Возврат после выдачи доступа.
9. Покупка во время активной sales-цепочки.
10. Открытая жалоба перед массовой кампанией.
11. Отписка в момент, когда сообщение уже в очереди.
12. Смена класса и учебника.
13. Два устройства и одна сессия ребёнка.
14. Удаление семьи при обязательных финансовых данных.
15. Уход сотрудника и отзыв доступа.

## После релиза

- ошибки;
- latency webhooks;
- дубли событий;
- delivery/bounce;
- расхождение оплат;
- жалобы;
- доступ без оплаты и оплата без доступа;
- необычные входы;
- размер базы и backup;
- ручная проверка 10 случайных карточек.
